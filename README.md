# 하루결 V1

메모를 원본으로 사용하는 개인용 로컬 우선 PWA. React + TypeScript + Vite. UI는 메모/일정 두 영역이며, 데이터 서버·AI·GPT API·계정·결제·광고·Android 공유 연동은 없습니다.

**처음 사용하는 분은 [시작하기.md](./시작하기.md)를 읽으세요.** Mac/Windows 더블클릭 실행 파일, 아이패드 설치, 백업·복구, 업데이트 순서를 담았습니다.

## 실행과 검증

Node.js 24 LTS를 권장합니다. 패키지별 요구 버전은 lockfile과 `engines`를 확인하세요. 개발 환경은 Node 26에서도 검증합니다. 전체 의존성 버전은 `package-lock.json`으로 고정했습니다.

```sh
npm ci
npm run dev
npm run check
npx playwright install chromium webkit
npm run test:browser
npm run package
```

- `check`: 단위테스트 → TypeScript 검사 → PWA 배포 빌드.
- `test:browser`: **먼저 build 필요**. 배포 빌드를 자동 실행하여 실제 브라우저로 검사합니다.
- `package`: 빌드된 `dist`를 `release/daynote-site.zip`으로, 수정 가능한 원본을 `release/daynote-source.zip`으로 묶습니다. 원본 ZIP에는 `.github/workflows`도 포함되며 `.git`, 설치 파일, 개인 백업은 제외됩니다.
- `시작-Mac.command` / `시작-Windows.cmd`: 최초 의존성 준비 → 검사/빌드 → localhost:4173 브라우저 열기.
- `배포파일-Mac.command` / `배포파일-Windows.cmd`: 검사/빌드 → 배포 ZIP 만들기.
- 개발 서버는 기본적으로 컴퓨터 내부에서만 열립니다. 다른 기기에서 사용할 주소는 HTTPS로 배포하세요.

## V1 동작 계약

| 항목 | 구현 |
|---|---|
| 메모 | 카드·체크박스·구분선 없는 줄 단위 자유 텍스트. Enter, 여러 줄 붙여넣기, 한글 조합 보호, 같은 원본 그룹 내 Backspace/Delete 합치기, 실행 취소/다시 실행 |
| 날짜 제목 | 줄 전체가 유효 날짜일 때만 인식. `261101`, `20261101`, `26/11.1`, `26/11/1`, `26-11-1`, `26.11.1` 모두 지원. 2자리 연도는 2000~2099년. 잘못된 날짜/문장 속 번호는 그대로 보존 |
| 날짜 표시 | 편집 중 원문, Enter/편집 종료 후 `26.11.1`로 표시. JSON 백업과 원문 내보내기에 입력 원문 유지. 미래순 정렬은 편집 중 보류. 날짜 그룹 사이 한 줄 높이 여백; 붙여넣은 경계의 빈 줄은 화면에서 접고 원문 보존 |
| 고정/완료 | 날짜 500ms 길게 누르기 → 그룹 전체 고정/해제, 이동 뒤 pointer capture와 클릭 차단으로 잘못된 편집 방지. 태스크 320ms 이내 더블탭 → 해당 줄만 완료. ⌘/Ctrl+Enter 대체 조작 |
| 화면 이동 | 메모/일정 탭 + 빈 여백 좌우 스와이프. 텍스트 편집 영역과 차트 가로 스크롤에서는 가로 제스처를 빼앗지 않음 |
| 일정 | 사용자가 ‘일정에 추가’를 실행한 줄만 등록. 일반 메모는 자동 등록하지 않음. 등록 후 원문 수정/완료는 같은 ID의 일정에 반영 |
| 기간 | 날짜 대신 기간 제목 또는 태스크의 명시한 기간 사용. `261101~~~1103` → `26.11.1~26.11.3` 표시. 짧은 종료일은 시작 연도만 상속, 연도 넘김 추측 없음. 그 외 제목 날짜의 하루 ◆ |
| 프로젝트 | 텍스트 드래그 선택 → 프로젝트 → 신규 표준명 또는 기존 프로젝트에 별칭 연결. 등록한 명칭/별칭이 문장 맨 앞에서 단어 경계까지 일치할 때만 자동 분류. 중간 일치·충돌은 미분류. 원문 치환 및 별칭만으로 일정 생성 없음 |
| 탐색 | 오른쪽 텍스트 없는 막대. 터치/길게 누르기/드래그 중 즉시 프로젝트 변경, 이동 중만 근처 토스트. 키보드 Tab/방향키/Enter와 접근성 이름 제공 |
| 중복 | 일정 DB 없음. 원본 줄 UUID를 키로 매번 계산하므로 재실행/편집 시 누적 중복 없음. 사용자가 일부러 같은 문장을 두 줄 적으면 서로 다른 할 일로 유지 |
| 원본 | 날짜 그룹의 화면 정렬은 원본 배열을 바꾸지 않음. 일반 지식과 입력 문자열 보존. 자유 메모는 별도 작은 라벨로 구분 |

예시:

```text
아이디어: 월별 자료는 따로 모아두기
26.11.20
A프로젝트 검토 회의
[프로젝트: 우리 집 수리] 공사 [26.11.16~26.11.20]
참고: 관련 자료는 PDF
26.11.13
B프로젝트 문서 전달
```

일반 지식은 날짜 아래를 포함해 자유롭게 작성합니다. 선택한 줄의 작은 메뉴에서 **일정에 추가/일정에서 해제**를 누르세요. 길게 누르기, 우클릭, Shift+F10으로 메뉴를 열 수 있으며 텍스트를 드래그 선택하면 **프로젝트**도 표시됩니다. 일정 화면은 원문에서 파생된 보기이며, 날짜 이동/수정은 메모에서 합니다. V1은 다중 줄 드래그 선택, 차트 드래그 수정, 자동 동기화, 알림을 지원하지 않습니다. 너무 긴 일정 범위를 한 번에 압축하지 않고 2주/한 달/3개월 구간으로 이동합니다.

## 저장·복구 설계

- 작은 텍스트 메모에 맞춰 **localStorage**를 사용합니다. IndexedDB보다 구현이 작고 매 입력 시 동기 저장되어 탭 종료 직전 debounce 대기 손실을 피합니다. 첨부 파일/대량 데이터가 필요해질 때 IndexedDB로 마이그레이션합니다.
- 앱 데이터 키 `daynote.v1`, 스키마 버전 2, 문서 revision, 원문 줄 UUID, 완료/고정, 수정 시각, 줄별 `schedule: {groupId} | null`, 표준 프로젝트 ID·이름·별칭. 서비스 워커 캐시와 사용자 데이터는 분리됩니다.
- 원본 크기 2MB, 최대 20,000줄을 지원 범위로 둡니다. 브라우저 전체 할당량 때문에 그보다 일찍 저장 실패할 수 있으며 **실패를 저장 완료로 표시하지 않습니다**. 실패한 최신 편집은 메모리에 남겨 ‘현재 화면 백업’으로 구조할 수 있습니다.
- 지원 브라우저에서는 Web Locks로 같은 출처의 한 창만 쓰게 합니다. 다른 창은 읽기 전용으로 두고 잠금이 풀리면 다시 읽습니다. 미지원 브라우저에서는 revision 비교와 storage 변경 감지로 충돌을 알리지만 엄밀한 동시 원자성은 보장하지 않으므로 한 창만 사용하세요.
- 읽기 오류가 난 저장소를 빈 문서로 덮어쓰지 않습니다. 저장소 원본 다운로드, 파일 복구 가능.
- 전체 백업 JSON은 입력 원문·완료·고정·일정 등록·프로젝트 별칭을 모두 포함. 가져오기 전 크기·스키마·타입·ID 중복·줄바꿈 검사. 줄 수 확인 후 명시적으로 교체하며 `daynote.before-import.v1`에 직전 저장 원문 1개 보관. 읽기용/원문 TXT는 가져오기 형식이 아닙니다.
- 메모는 암호화되지 않은 브라우저 내부 데이터입니다. 브라우저 데이터 삭제/저장 공간 회수/앱 제거에 대비해 외부 파일 백업이 필요합니다. 기기·브라우저·웹 출처가 다르면 저장소가 다릅니다. 같은 출처의 다른 경로와 저장 키를 공유하므로 하루결은 한 출처에 한 인스턴스를 권장합니다.

## PWA·배포

- manifest에 standalone, 상대 start_url/scope, 192/512px PNG 아이콘과 Apple touch icon을 포함합니다. 코드로 그린 단순 아이콘이고 외부 폰트/이미지/CDN 요청은 없습니다.
- `vite-plugin-pwa`/Workbox가 빌드 때 앱 파일을 precache합니다. 최초 온라인 접속/서비스 워커 준비 이후 오프라인 재실행·편집을 지원합니다. 개발 서버에서는 기본적으로 SW를 설치하지 않습니다.
- 업데이트는 prompt 방식입니다. 실행 중 새 버전으로 강제 교체하지 않고, 사용자 버튼으로 적용합니다. 앱 전환으로 다시 돌아왔을 때 업데이트 확인. 데이터 키와 스키마는 유지합니다. 후속 스키마 변경에는 별도 마이그레이션 테스트가 필요합니다.
- HTTPS 배포 또는 localhost에서 서비스 워커를 사용할 수 있습니다. `file://`로 index.html을 여는 것, 사설 IP의 단순 HTTP는 아이패드 설치/오프라인 확인 방법이 아닙니다.
- `base: './'`와 상대 manifest 경로로 GitHub Pages 하위 경로를 지원합니다. 저장소 이름을 바꿨다면 설치 주소·저장소를 다시 확인하고 백업으로 옮기세요.
- `.github/workflows/pages.yml`: main push → 단위/타입/빌드 → Chromium/WebKit 브라우저 테스트 → Pages 배포. GitHub Pages의 Source를 GitHub Actions로 한 번 설정해야 합니다. 외부 저장소/실제 배포는 사용자 계정에서 진행합니다.
- `release/daynote-site.zip`은 별도의 HTTPS 정적 호스팅에도 배포할 수 있습니다. 압축 해제한 최상위에 index.html이 오도록 하세요.

## 코드 위치

- `src/model.ts`: 순수 날짜/그룹/기간/프로젝트/백업 규칙.
- `src/storage.ts`: 저장 읽기·크기·revision 충돌 검증.
- `src/Editor.tsx`: 입력, 한글 조합, 터치, 고정, 커서 유지.
- `src/ProjectMenu.tsx`: 선택한 표현의 신규 프로젝트/기존 별칭 등록.
- `src/Timeline.tsx`: 하루/기간 타임라인과 프로젝트 스크럽.
- `src/App.tsx`: 자동 저장, 쓰기 잠금, 백업/복구, PWA 업데이트.
- `src/model.test.ts`: 규칙·원문 보존·저장 오류 단위테스트.
- `tests/app.spec.ts`: 실제 배포 빌드의 입력/제스처/오프라인/복구 검사.

## 실기기 확인 체크리스트

자동 브라우저 검사는 실제 M1 iPad의 Safari·가상 키보드·홈 화면 앱을 완전히 대신하지 않습니다. 설치 후 아래를 확인하세요.

1. 한글 문장을 조합하고 Enter, 수정, 두 번 누르기.
2. 날짜 0.5초 누른 후 손을 뗐을 때 다른 문단이 편집되지 않는지.
3. 스크롤 중 고정이 발생하지 않는지, 여백 좌우 이동/차트 가로 스크롤/프로젝트 스크럽 구분.
4. 홈 화면 앱에서 비행기 모드 재실행 → 작성 → 종료 → 재실행 보존.
5. 파일 앱에 백업 저장 → 가져오기 → 완료/고정/원문 보존.
6. 새 버전을 배포하고 업데이트 버튼 적용 후 데이터 유지.

## 2026-11-22 변경: 수동 등록과 별칭

- 등록 상태를 기존 줄 데이터에만 추가하여 원본 줄 UUID가 곧 일정 ID입니다. 일정의 그룹 ID는 날짜 제목 줄을 가리킵니다. 별도 일정 복사본을 만들지 않습니다.
- 같은 줄 등록은 멱등적이며, 줄 삭제/빈 내용/날짜 제목으로 전환 시 일정도 제거합니다. 등록 해제는 메모를 그대로 둡니다. 줄 합치기로 사라지는 ID의 등록은 제거하며, 분할은 첫 줄에만 등록을 유지합니다. 실행 취소는 원문·등록·프로젝트를 함께 복원합니다.
- 날짜 제목이 수정 중에 잘못된 날짜가 되면 등록을 유지한 채 일정을 숨기고 안내합니다. 이전 날짜 그룹에 잘못 붙이지 않습니다. 올바른 날짜로 고치면 복원합니다. 날짜 제목 줄 자체가 삭제되면 연결 등록을 해제합니다. 유효한 새 제목을 삽입해 그룹을 나누면 해당 그룹 ID로 갱신합니다.
- **schema 1 이관:** 구버전에서 실제 표시되던 일정만 한 번 등록된 상태로 보존합니다. 새 메모는 등록하지 않습니다. 기존 인식 프로젝트 이름을 고유 ID로 옮기되 이후 분류는 새 문장 시작/경계 규칙을 적용합니다. 과거 문장 중간에서 잘못 인식된 프로젝트는 미분류가 됩니다. 원문·ID·완료·고정은 보존합니다.
- 읽기는 메모리에서 이관하고, 첫 저장 직전에 원래 JSON을 `daynote.before-schema2.v1`에 한 번 보관합니다. 백업 보관 실패 시 저장을 중단합니다. 앱의 **이전 버전 저장본 받기**로 내려받을 수 있습니다. 스키마 1/2 백업 모두 가져오며, 미지원 미래 버전/중복 ID/끊어진 그룹 참조는 거부합니다.
- 등록한 별칭은 프로젝트 ID와 연결됩니다. 이름 자체도 일치 대상으로 사용하며, 한 문장이 두 프로젝트와 일치하면 긴 표현을 임의로 선택하지 않고 미분류로 둡니다. UI에서는 이미 다른 프로젝트에 등록된 동일 표현의 중복 등록을 거부합니다.
- 기존 UI·저장 방식·배포 경로를 유지하고 라이브러리/AI/API를 추가하지 않았습니다. 기존 화면은 Gantt 타임라인이며 별도 달력 화면을 추가하지 않았습니다.

이번 변경 검증: 단위테스트 **54개**, Chromium/WebKit 브라우저 검사 **28개**, TypeScript 검사와 배포 빌드 통과. 신규 메모 미등록, 단일 줄 수동 등록/해제, 중복 방지, 날짜/내용 연결 갱신, 별칭 드래그 등록, 문장 중간 미분류, 기간 표기, 기존 데이터 이관, 날짜 고정 후 오클릭 방지, 터치 더블탭, 실행 취소/다시 실행, 실제 JSON 다운로드·복구를 확인했습니다. 실제 iPad의 기본 텍스트 선택 메뉴·가상 키보드 동작은 실기기 확인이 남아 있습니다.

### 선택 메뉴 후속 수정

- React `onSelect` 외에 네이티브 `selectionchange`/`select`를 직접 처리합니다. Safari의 문서/textarea 이벤트 경로를 모두 받으며, 터치로 태스크를 길게 누를 때 기본 텍스트 선택을 취소하지 않습니다. 날짜 고정의 이벤트 차단은 유지합니다.
- 선택 중 스크롤이나 화면 크기 변경이 발생하면 메뉴 위치를 다시 계산합니다. `visualViewport` 변경도 반영하며 터치 선택 메뉴는 키보드 위쪽에 놓아 기본 선택 메뉴와 겹침을 줄입니다.
- 단위테스트 **54개**, Chromium/WebKit **32개**, 빌드 통과. 추가 검사는 스크롤 후 메뉴 유지, 모의 키보드 영역 변경, 네이티브 선택 이벤트, 터치 기본 메뉴 허용과 별칭 등록을 포함합니다. 실제 iPad의 OS 선택 손잡이와 키보드는 자동화로 재현하지 않았으므로 실기기 확인은 남아 있습니다.
